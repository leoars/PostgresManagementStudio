# User guide

English | [Português (Brasil)](../pt-BR/user-guide.md)

## Connect and query

Open **New Query** (`Ctrl+N`), then **Connect**. Enter host, port, database, role and TLS settings. The default VerifyFull requires a trusted certificate and matching hostname. **Test Connection** checks the connection without saving a profile. Save a profile explicitly; password storage is optional and protected by Windows DPAPI. Each query tab owns its own PostgreSQL session. Switching database needs a connection, not a SQL Server `USE` command. T-SQL is not translated. For certificate authentication, set **Client certificate**, **Client key** and, for an encrypted key, **Key password** (stored with DPAPI when you save it); backup and restore pass that password to the PostgreSQL tools through a temporary private service file.

Use `F5` to execute the selection or document and **Cancel** to request cancellation. Cancellation does not prove that a server-side command or COMMIT was rolled back. Inspect the result before repeating a write. Results/Messages show results and diagnostics. Read timeout, server session settings and explain plans have dedicated controls. **Analyze Plan** executes SQL and requires review; use it only when that execution is intended. SQL with `$1`-style placeholders cannot run without parameter values: PGMS refuses it before sending, keeps the session open and points to the placeholder. `PREPARE` and function/procedure bodies are exempt, and **Estimated Plan** switches to a generic plan.

Results are bounded: 10,000 rows, 100 result sets, 256 columns per result, 4,096 columns total and 250,000 cells, with additional text limits. Warnings explain omitted data; later SQL can still execute. CSV/JSON export covers retained displayed/selected data, not a full database export. `Ctrl+C` copies with headers; `Ctrl+Shift+C` omits headers. Copy is limited to 250,000 positions/4Mi UTF-16 units and distinguishes NULL from empty text.

## Inspect and administer

Object Explorer loads folders on demand, filters and inspects objects. Supported operations offer SQL preview and explicit Apply. Script output does not include all concurrent-change protections of Apply. Use the least PostgreSQL privileges required; PGMS does not bypass server authorization. Check target database/schema/object and role before applying.

Identity and sequence operations distinguish configured START from RESTART. A restart can repeat existing values. The **Partitions** dialog creates, attaches and detaches partitions. A new child can itself be partitioned (**Sub-partition by**, keyed by columns of the parent), and a partitioned table can be attached or detached with its sub-tree. **Detach concurrently** runs `DETACH PARTITION … CONCURRENTLY` outside a transaction, without blocking queries; it is refused for a DEFAULT partition or while another detach is pending, and a pending detach is finished with `FINALIZE`. Privilege changes, delegation, CASCADE and COMMIT reconciliation have specific review and concurrency rules. See the [documentation index](../README.md) for supported behavior.

**Script as.** The menu of a database, schema, table, view, materialized view, sequence, function, procedure, enum, domain, index, key, constraint, trigger or role has **Script … as** with **CREATE To**, **DROP To** and the verbs that apply, each to **New Query Editor Window**, **File…** or **Clipboard**, as in SSMS; verbs that do not apply stay gray. Tables show **Keys**, **Constraints** and **Triggers** folders. An index has **Rebuild** (`REINDEX`) and the Indexes folder **Rebuild All**. **Tasks ▸ Take Offline** and **Bring Online** set `ALLOW_CONNECTIONS` of a database: PostgreSQL refuses new sessions and leaves the open ones running, and Object Explorer shows the database as `name (Offline)`.

## Database diagrams

In Object Explorer, right-click **Database Diagrams** under a database and choose **New Database Diagram**. The first time, PGMS asks to create its support objects (schema `pgms`). Add tables with **Add Table** or **Add Related Tables**, drag a column onto another to create a foreign key, and use **Arrange Tables** to lay them out. Saving shows the SQL script of any change to the database for review. **Table View** in the toolbar changes the selected tables; with no table selected it changes every table of the diagram, in one step of Undo.

**Indexes.** Each table shows an **Indexes** section below its columns, closed by default so diagrams laid out before keep their spacing: the header gives the count and the methods other than b-tree (for example `Indexes (3) · GIN`), and its tooltip lists every index. Click the header to show one row per index: name, method when it is not b-tree (Hash, GIN, GiST, SP-GiST, BRIN), key columns or expressions, the operator class when it is not the default (such as `gin_trgm_ops`, `jsonb_path_ops` or `text_pattern_ops`), `INCLUDE` columns, and UNIQUE, EXCLUDE, partial or invalid. The row tooltip has the predicate of a partial index and the full `CREATE INDEX`. A gold key marks the primary key, a silver key a unique or exclusion constraint, and a tree a plain index. A warning triangle in the title marks a table with a foreign key that no index serves, by the same rule as **Find Unindexed Foreign Keys…**; click it, or use the item of the table menu, to open that window for that table only, already scanned (from Object Explorer it covers the whole database and waits for **Scan**). **Show Indexes** in the diagram menu turns the sections and the warning off and on for that diagram, and **Refresh** reads the tables and their indexes again. The section is read only: create or change indexes in **Indexes/Keys…** (double-click an index row) and the other dialogs. Every save writes the indexes of each table, read from the catalog inside the save transaction, into the diagram definition (`pgms.diagrams.definition`), so tools and AI agents that read the diagram see them; changes made only in the database do not mark the diagram as changed and reach the definition on its next save. Diagrams saved by earlier versions open as they were and are written in the new format by their next save. SSMS 22.11 shows no indexes in a diagram; this section is a PGMS addition.

## Query Designer

**Query ▸ Design Query in Editor** (`Ctrl+Shift+Q`) opens the statement under the cursor, or the selection, in the Diagram, Criteria and SQL panes. **OK** replaces that statement in the editor; nothing is executed. On an empty line it starts empty and inserts at the cursor. `UNION` and `WITH` open only in the SQL pane.

## IntelliSense

`Ctrl+Space` or `Ctrl+J` opens the list; typing a dot opens it by itself. `Tab` accepts and `Esc` closes. **Query ▸ IntelliSense Enabled** (`Ctrl+B`, `Ctrl+I`) turns it off for the tab, and **Edit ▸ IntelliSense ▸ Refresh Local Cache** (`Ctrl+Shift+R`) reads the catalog again after schema changes. After `FROM` and similar keywords it searches table names in every user schema; after `JOIN` it offers whole joins from foreign keys. Parameter Info and Quick Info are described under [Editor](#editor).

## Execution plans

**Display Estimated Execution Plan** (`Ctrl+L`) and **Include Actual Execution Plan** (`Ctrl+M`) draw the plan as operators linked by arrows proportional to the rows. **Warnings.** In an actual plan, an operator whose filter discarded many rows gets a yellow triangle, and its tooltip and properties have a **Warnings** section with the counts of Filter, Join Filter and Index Recheck. It is a PGMS rule, not a PostgreSQL warning: by default it appears when the discarded rows are at least 10 times the rows returned and at least 1,000, both set in **Query Options ▸ Execution ▸ Advanced** and, for new tabs, in **Tools ▸ Options**. **Missing index.** When a warned scan filters by simple comparisons, the plan header gets a green line with a suggested index and the context menu enables **Missing Index Details…**, which opens a query tab with the `CREATE INDEX` (and a `CONCURRENTLY` variant) commented out; nothing runs. The suggestion is a heuristic (equality columns first, then the `ORDER BY` under a `LIMIT` or one range column) checked against the catalog, so it is not offered when a valid b-tree index already starts with those columns. It does not cover joins, `OR`, expressions or `INCLUDE`, and it does not estimate selectivity: test it before creating the index.

**Text, JSON and comparison.** The context menu of a plan (in the query tab or in its own tab) has **Show Execution Plan JSON**, the server's JSON indented in a new tab, and **Show Execution Plan as Text**, the layout of `EXPLAIN` in text built from that JSON without running the query again. **Compare Showplan** compares the plan with a saved plan file, and **Compare with Previous Plan** with the plan the same tab had before. The **Showplan Comparison** tab shows both plans side by side; operators matched by name and depth that have other values are shaded amber in both drawings, operators that exist in only one plan are shaded pink, and the **Differences** grid lists the totals and each operator. There is no Analyze, which in SSMS looks for SQL Server scenarios.

## Generate SQL with AI

**Query ▸ Generate SQL with AI…** sends your request and the structure of the database (names, types, keys, comments; never table data) to the provider set in **Tools ▸ AI Assistant Settings…**: Anthropic, OpenAI or a local Ollama, with your own key, stored encrypted for your Windows user. The SQL is shown for review and only inserted into the editor. The structure sent is limited by **Context limit** in the settings (200,000 characters by default). When the database does not fit, PGMS first sends only the table names, with their comments, and lets the provider choose the relevant tables; then it sends those tables, the tables their foreign keys reference and the tables whose names share words with your request. Tables left out are listed by name. **View Sent Context…** shows what was sent in each call. The first call costs tokens too.

**Conversation.** After a result, type a follow-up request (for example, "also filter by status"): the last five requests of the conversation and the SQL written for them go with it. **New Conversation** clears them; closing the window ends the conversation. **Query ▸ Explain SQL with AI**, **Fix SQL with AI** and **Optimize SQL with AI** open the window with the selected SQL, or the document, and a request already written that you can edit. **Fix** adds the SQLSTATE and the main message of the last error of the tab, shown in the request before sending; the DETAIL of the error, which can quote row values, is never sent. Nothing is sent until you press **Generate**, and the SQL is only inserted into the editor. With Ollama, PGMS reads the model's maximum context and asks for a window that fits the prompt, trimming the structure (and saying so) when it does not fit.

## Large results

A grid result larger than **Query Options ▸ Results ▸ Grid ▸ Rows per result page** (100,000 by default) is shown in pages, with a bar below the grid. Rows after the first page are kept in a temporary file until the next execution or until the tab closes. Sorting, copy and export apply to the current page; **Results to File** writes every row.

## Activity Monitor

**View → Activity Monitor** (`Ctrl+Alt+A`) opens a document tab for the connected server and role (`host:port (role) - Activity Monitor`); opening it again activates the same tab. It has six collapsible panels, following the SSMS layout:

- **Overview**: charts of active sessions, waiting sessions, database I/O (`pg_stat_io`) and transactions per second. Its context menu sets the refresh interval and pauses, resumes or refreshes the whole monitor.
- **Processes**: sessions from `pg_stat_activity` with host, state, query and transaction age, wait, **Blocked by PID** and **Head blocker**, filters applied on the server and pages by PID. **Details…** opens the session's most recent query; **Cancel Query** and **Terminate Session…** act on the selected session.
- **Resource Waits**: wait categories sampled at each refresh. PostgreSQL keeps no cumulative wait time, so these are estimates; idle waits and `pg_sleep` are left out.
- **Data File I/O**: reads, temporary writes, read time and buffer hit per database (`pg_stat_database`), not per file: PostgreSQL has no per-file statistics.
- **Recent Expensive Queries**: the change in `pg_stat_statements` between refreshes; requires the extension, as Query Statistics does.
- **Active Expensive Queries**: statements running now. **Edit Query Text** opens one in a query tab; **Show Execution Plan** shows an estimated plan without executing it.

Auto-refresh starts on, every 10 seconds, with intervals from 1 second to 1 hour. **Cancel Refresh**, **Cancel Query** and **Terminate Session** are distinct actions; refreshing a snapshot is not authorization to terminate a session. Pages are separate reads, so a session can move between pages, and sorting applies within the loaded page. Roles outside `pg_read_all_stats` may not see other roles' queries and waits.

## Query statistics

**View → Query Statistics…** reads `pg_stat_statements` for the connected database: normalized statements with calls, execution time (total, mean, minimum, maximum, standard deviation), rows, cache hit %, shared and temporary blocks, I/O time and WAL bytes. The purpose is similar to SQL Server Query Store; it is not a copy of its screens or reports.

PGMS never loads, creates or configures the extension. The server needs `shared_preload_libraries = 'pg_stat_statements'` (a restart) and `CREATE EXTENSION pg_stat_statements` in a database; when something is missing, a yellow band says what. Roles outside `pg_read_all_stats` see other users' statements without SQL text, as PostgreSQL decides. I/O time is only recorded with `track_io_timing` on. PostgreSQL has no per-statement CPU time. Extension version 1.10 (PostgreSQL 16) is read without `stats_since`: a statement removed and tracked again during a time window can count low, and the window status says so. Versions older than 1.10 are not read; the band names the `ALTER EXTENSION pg_stat_statements UPDATE` a privileged user can run, and PGMS changes nothing.

Filters (database, user, SQL text, minimum calls) and ordering run on the server before a 1,000-row limit. Clicking the Total, Mean, Max, Calls, Rows or metric headers reloads in that order; other headers sort only the loaded rows. **Window** shows cumulative values since the last reset, values since a saved baseline, or the last 5/15/60 minutes, computed by subtracting an earlier reading; sliding windows sample only while the window is open, and minimum/maximum are not available for a window. A top-N chart beside the grid follows the applied order. **Show Plan** opens the selected statement in a new query tab with `EXPLAIN (GENERIC_PLAN)`, without executing it or binding `$n` values. **Reset Selected** and **Reset All** call `pg_stat_statements_reset` after a confirmation whose default is No; the server decides whether the role may reset. Auto-refresh is optional and starts off. Filters, chart choices and baselines are stored per connection target in the PGMS state folder, without passwords or SQL results.

**Descriptions.** A table, a column or a relationship can have a description: it is the PostgreSQL `COMMENT ON` of that object, so every tool that reads the catalog sees it. A small page icon marks a described table (in its title), column (at the end of its row) and relationship (on its line), and its tooltip shows the text. Right-click and choose **Table Description…**, **Column Description…** or **Relationship Description…**, or click the icon, to open **Description Property**: free text of several lines, up to 4 KiB of UTF-8. The change stays in the diagram, the table shows `*`, and **Save** applies it with `COMMENT ON` after the script review, like every change made in a diagram; **Generate Change Script…** shows it before. A change that is only descriptions does not lock the table: PGMS checks that the table, column or key is still the one the diagram read (by OID and name) and that nobody changed that description in the meantime. PostgreSQL lets only the owner of a table change its descriptions. When you do not own it, Save keeps the description only in the diagram, marked as not applied (an orange icon), and then shows the script to send to the owner; **Script Unapplied Descriptions…** in the table menu shows it again, and once the owner runs it the mark goes away. **Description Property** can also put that text back in the box or discard it. Each save writes a copy of the descriptions into the diagram definition (format 3), with the time the catalog was read. When the diagram opens or you choose **Refresh**, the catalog wins: if a description changed in the database since the save, the diagram shows the new text with an orange icon whose tooltip has the old copy, and the next save updates the copy. In SSMS 22.11, descriptions are edited in the Properties window of the diagram and saved as `MS_Description`; the icons, the copy and the export below are PGMS additions.

## Using diagrams with AI agents

An AI agent that writes SQL without seeing the model guesses column names and misses the indexes. A diagram with descriptions is that model, in three forms:

- **The catalog.** Descriptions are `COMMENT ON`, so an agent connected to the database (through psql, an MCP server of your choice or any client) reads them with `obj_description` and `col_description`, or `\d+` in psql.
- **Export for AI…** in the diagram menu writes the tables of the diagram as Markdown: an instruction for the agent at the top, then each table with its description, columns (type, null, default, description), keys and checks, foreign keys (with a note when no index serves one), the tables that reference it, and its indexes with their full definition, including the method and operator class (such as `gin_trgm_ops`). Tables and items come in a fixed order, so the same database gives the same text. **Copy** puts it on the clipboard and **Save As…** writes a `.md` file, ready for a system prompt, a `CLAUDE.md` or an `AGENTS.md`. The export reads the database as it is now: unsaved changes of the diagram are not in it.
- **`pgms.diagram_markdown(name)`**, optional. **AI Export Function…** in the diagram menu, or the box in **Install Diagram Support** (unchecked by default), creates this function in the schema `pgms` after you review its script. `SELECT pgms.diagram_markdown('Sales');` returns the same Markdown as the export, read from the catalog, for the saved diagram with that name, or NULL when there is none. It is read only, runs with the privileges of the caller, who needs `SELECT` on `pgms.diagrams`, and the same dialog removes it.

The saved diagram itself is the JSON in `pgms.diagrams.definition`: tables, positions, indexes and the copy of the descriptions, with `"applied": false` on descriptions that are not applied in the database.

An example of an instruction for the system prompt of an agent:

> Before writing SQL for the Sales database, read `docs/database-model.md` (exported from PGMS) or run `SELECT pgms.diagram_markdown('Sales');`. Use only the tables and columns listed there, with the names as written. If something you need is not there, ask instead of guessing a name. Check the indexes before filtering, joining or sorting large tables.

PGMS has no MCP server of its own.

## Backup and restore

Choose compatible PostgreSQL tools and a new output file/directory. Custom, tar, plain SQL and directory formats support the documented content choices. Restore goes into the selected database; with the server or the Databases folder selected, PGMS asks for it, and a new name creates the database (`TEMPLATE template0`) after confirmation; compatible objects/roles and permissions must already exist where required. Ownership and privileges are explicit choices. Directory backup supports parallel dump. Compression can be gzip, LZ4 or Zstandard, with their levels. **Restore** accepts parallel jobs (1–32); above 1 it cannot use a single transaction, and the window warns. **Restore only chosen items** with **Choose Items…** lists the archive contents (`pg_restore --list`) and restores only the checked items; items they depend on are not added automatically. Global operations cover roles/memberships/tablespaces, not a physical cluster backup.

Only run trusted SQL scripts: psql scripts may include local commands, reconnects and COMMIT. Single-transaction options cannot override those commands. Cancellation can arrive after a commit. Encrypted client keys, CR/LF in tool passwords and non-ASCII TEMP paths have documented restrictions. Keep the source backup unchanged and inspect the destination after failures. The [distribution guide](distribution.md) describes tools, permissions and package requirements.

## Query History

**View ▸ Query History…** (`Ctrl+Alt+H`) lists the SQL executed in query tabs: `F5`/**Execute** with results to grid, text or file, SQL written by Query Designer or **Generate SQL with AI**, scripts opened by **Script as** and similar tools, and **Execute SQL** inside the Query Designer. Each execution keeps the SQL (up to 64 KiB by default; longer text is cut and marked), server, port, database, user, start time, duration, rows, result (SQLSTATE and message on errors, or canceled) and origin. SQL refused before it is sent, such as text with unbound `$1` placeholders, is not recorded. SSMS 22.11 has no built-in equivalent.

Repeated queries are grouped: one row per distinct SQL on the same server, port and database (runs of spaces and line breaks are ignored, case is not), with the last run and the count. **+** or the right arrow lists each execution. Filter by text, connection and period. **Open in New Query** puts the SQL in a new tab, connected when PGMS already has a connection to that server and user, and never executes it. **Pin** keeps a query on top and its newest execution is never removed by the limits.

**Privacy and storage.** Query History is stored only on this computer, in `%LOCALAPPDATA%\PGMS\history`, encrypted with Windows DPAPI for the current Windows user. It is never written to a server. SQL can hold sensitive values, such as literals or a password typed in `ALTER ROLE … PASSWORD`: anyone signed in as your Windows user can read it in PGMS. Limits and the on/off switch are in **Tools ▸ Options ▸ Query Execution ▸ Query History** (defaults: 90 days, 10,000 executions, 64 KiB per execution); **Clear History…** deletes everything. To record nothing for a server, such as production, check **Do not record query history for this server** in its saved connection profile; it applies to every connection to that host and port. Writing the history never delays or fails a query: a failure only shows a message in the status bar.

## Editor

**Edit ▸ Advanced** has the SSMS editing commands: comment and uncomment lines or blocks, upper and lower case, move, sort, join and duplicate lines, delete horizontal white space, tabify/untabify, increase and decrease indent, **Insert File As Text**, **Expand Selection** (`Shift+Alt+=`: word, quotes, parentheses, statement, document), **Containing Block**, **Expand to Line**, next/previous subword and **Incremental Search**. **Format SQL** (`Ctrl+K`, `Ctrl+Q`) lays out the selection or the document; only spaces, line breaks and the case of keywords change, and text it cannot read is left as it is. **Toggle Spell Checker** checks comments and strings with the Windows spell checker, in the language of Windows or in English, per tab.

The information bar under the editor has the zoom (20–400 %, `Ctrl`+wheel), line and column (click for Go To Line), tabs or spaces, line ending and encoding. **Set End of Line Sequence**, **Set Indentation** and **Set Encoding** convert the whole document in one Undo step; only Unicode encodings are offered.

**IntelliSense ▸ Parameter Info** (`Ctrl+Shift+Space`, also when typing `(` or `,`) shows the arguments of a function, and **Quick Info** (`Ctrl+K`, `Ctrl+I`, or the mouse) describes a table, column or function. **Bookmarks** (`Ctrl+K`, `Ctrl+K` to toggle, `Ctrl+K`, `Ctrl+N`/`Ctrl+P` to move) belong to each tab. **Outlining** folds statements of more than one line and block comments.

**Template Explorer** (`Ctrl+Alt+T`) lists PostgreSQL templates and your own `.sql` files from the `Templates` folder of the PGMS state directory; **Specify Values for Template Parameters** (`Ctrl+Shift+M`) fills `<name, type, value>` placeholders. **Insert Snippet** (`Ctrl+K`, `Ctrl+X`) and **Surround With** (`Ctrl+K`, `Ctrl+S`) insert snippets; `Tab` moves between fields.

When the server reports the position of an error, the editor underlines it, the information bar counts it and **Go To Next/Previous Issue in File** (`Alt+PgDn`/`Alt+PgUp`) reaches it; editing clears it. **Find in Files** and **Replace in Files** (`Ctrl+Shift+H`) search a folder (`*.sql` by default), the open documents or the current one, and list the matches in **Find Results**; Replace All changes open tabs in the editor and other files on disk, with the same encoding, after a confirmation. **Edit ▸ Show Clipboard History** (`Ctrl+Shift+V`) keeps the last 20 copies in memory, and **Go To Last Edit Location** (`Ctrl+Shift+Backspace`) returns to the last change, even in another tab.

A line longer than 10,000 characters is shown cut, with a marker that opens the whole line; the file and the SQL that runs are not changed.

**Edit ▸ Paste Special ▸ Format SQL** pastes the clipboard formatted (one Undo), and **Paste with AI…** opens Generate SQL with AI with the pasted SQL; nothing is sent until you press Generate. **Edit ▸ IntelliSense ▸ Switch Completion Mode** (`Ctrl+Alt+Space`) toggles suggestion mode, where `Enter` keeps what you typed and `Tab` inserts the suggestion. **File ▸ New ▸ File…** (`Ctrl+Alt+N`) creates a SQL file, a text file or a SQL file from a template, and **Tools ▸ Code Snippets Manager…** (`Ctrl+K`, `Ctrl+B`) imports `.snippet` files into your snippets folder.

## Tabs, windows and settings

**File ▸ New ▸ Query with Current Connection** (`Ctrl+N`) uses the connection of the active tab or of Object Explorer; **Database Engine Query** asks for one. **Open ▸ File…** connects the new tab the same way, and **File Disconnected…** opens without connecting. **File ▸ Recent Files**, **Save All**, **Window ▸ Close All Tabs** and **Restore Closed Tab** work as in SSMS; a closed query without a file comes back with its text, disconnected. **Window** also has **Next/Previous Pane** (`F6`/`Shift+F6`), **Show Results Pane** (`Ctrl+R`), **Split Tab**, **Dock**, **Auto Hide**, **Move To New Window**, up to ten saved window layouts and **Auto Hide All**; **View ▸ Full Screen** is `Shift+Alt+Enter`, and in Full Screen **View ▸ All Windows** (`Shift+Alt+M`) hides and shows the tool windows. **View ▸ Navigate Backward/Forward** (`Ctrl+-`, `Ctrl+Shift+-`) returns to earlier places: tab changes and jumps of ten or more lines. **Window ▸ Pin Tab** keeps a tab at the start, with a pin, and **Close All Tabs** leaves it open; a pinned tab stays pinned when it is recovered after a crash or reopened with Restore Closed Tab. Message boxes are drawn by PGMS, in the PGMS language, with `Enter`, `Esc`, access letters and `Ctrl+C` to copy their text.

The menu shares the title bar with the window buttons and **Search** (`Ctrl+Q`), which finds menu commands and Tools ▸ Options pages and settings; `Enter` runs or opens the result. **View ▸ Properties Window** (`F4`) shows the session of the active query (server, login, database, backend PID, version, SSL mode, last execution). **View ▸ Error List** (`Ctrl+\`, `E`) has the error of the last execution of each open tab; double-click goes to it. **View ▸ Output** (`Ctrl+Alt+O`) keeps the messages and executions of the session (5,000 lines in memory). **File ▸ Page Setup…** and **Print…** print the SQL of the active tab.

**Tools ▸ Options** includes **Fonts and Colors** (editor, Grid Results and Text Results), **Keyboard** (one shortcut per menu command, which wins over the built-in one), **Query Shortcuts** (`Alt+F1`, `Ctrl+1` to `Ctrl+0`, empty by default; the text runs in the session of the active tab, followed by the selection), Object Explorer **Scripting**, **Designers** and **Connection Dialog**. **Tools ▸ Theme** lists the 13 SSMS themes in the SSMS order (Cool Breeze is the default; Light is the SSMS gray; Dark; and the color themes) and **Use system setting** (Cool Breeze when Windows is light, Dark when it is dark); in Dark, diagrams and graphical plans stay light. **Tools ▸ Editor Appearance** sets the editor colors separately, with two extra-contrast modes, and **View ▸ Presenter Mode** (`Ctrl+Shift+F5`) enlarges the editor, results and window text for the session. **Tools ▸ Import and Export Settings…** saves, loads or resets the Options in a `.pgmssettings` file (without window position, recent files, connections, passwords or AI settings). **Tools ▸ External Tools…** adds programs to the Tools menu, run only when you choose them, and **Tools ▸ Customize…** shows or hides the toolbars.

More Options pages follow SSMS 22.11; options PGMS cannot apply are shown disabled with the reason:

- **Environment ▸ AutoRecover:** back up unsaved queries every 5 minutes by default (1 to 60), and discard copies older than 7 days. A crash loses at most the changes of the last interval.
- **Environment ▸ Documents:** a file changed outside PGMS is reloaded when PGMS becomes active (it asks first when the tab has unsaved changes); read-only files open without editing unless allowed; File ▸ Open starts in the folder of the active file; mixed line endings can be normalized to CRLF when a file opens; save in the background when PGMS loses focus; save every file in a chosen Unicode encoding.
- **Environment ▸ Tabs:** **Insert new tabs to the right of existing tabs** is off by default, as in SSMS, so a new tab goes first, after the pinned tabs. Recovered queries always come back after the open tabs, in their saved order. **Windows:** applying a saved window layout asks first unless the confirmation is skipped.
- **SQL Formatter** (seven pages): keyword casing, Format on save, aligned clause bodies, indentation size, lists on several lines, new lines before clauses and joins, blank lines between statements and a space between a type and its parameters (on by default, `VARCHAR (20)`).
- **Designers ▸ Table Options:** a Table Designer statement that runs longer than the time-out (on, 3600 seconds) stops the save and nothing is changed; optional warning before saving a table without a primary key.
- **Object Explorer ▸ General:** **Hide system objects** is off by default, as in SSMS: `pg_catalog`, `information_schema` and the template databases are listed (after a refresh when you change it). **Commands:** renaming a key, constraint or trigger in place asks first.
- **Query Execution ▸ Live Query Statistics:** how often live statistics are read (250 ms by default).
- **Text Editor ▸ Transact-SQL:** word wrap, line numbers, tab size and spaces, and IntelliSense.
- **Environment ▸ International Settings:** the interface language (see below). **Product Updates:** the update notice.

**Languages.** The interface is available in English, Português (Brasil), Español, Deutsch, Italiano, Français, 한국어 and 日本語. **Same as Microsoft Windows** (the default) follows the Windows display language, or English when Windows uses another one; the language changes when PGMS starts again. Object Explorer folder names, command names in the Keyboard page, SQL, data and server messages stay in English or as they are. The translations have not been reviewed by native speakers yet; please report problems with the [translation form](https://github.com/leoars/PostgresManagementStudio/issues/new?template=translation.yml).

**Update notice.** A few seconds after start, a release package asks the GitHub API (`api.github.com`) for the list of PGMS releases; GitHub sees your IP address, as with any web request, and nothing else is sent. When a newer version exists, **Update available** appears in the title bar, next to Search, with **Open the release page**, **Skip This Version** and the options. Nothing is downloaded or installed. **Help ▸ Check for Updates** asks at once; **Tools ▸ Options ▸ Environment ▸ Product Updates** turns the automatic check off. A failed automatic check is silent.

## Results and running queries

Results, Messages, the plan and the session tabs are above the results. **Save Results As…** in the grid menu opens **Save Grid Results**: a `.csv` file separated by commas or a `.txt` file separated by tabs, always with headers, for the current page. **Export Options…** opens the CSV/JSON export band. Several result sets of one execution are shown in tabs, or stacked in one tab when **Tools ▸ Options ▸ Query Results ▸ Results to Grid ▸ Show multiple result sets stacked in one tab** is on. PostGIS `geometry` and `geography` values are shown as EWKT (`SRID=4326;POINT(1 2)`, the same text as `ST_AsEWKT`) in the grid, Results to Text, copy and export, and Table Designer accepts types such as `geometry(Point,4326)`. Other extension types are shown as the text the server sends; after a type PGMS does not know yet, the session reads the types again.

**Query ▸ Include Live Query Statistics** adds a tab that, every 250 ms by default (Tools ▸ Options ▸ Query Execution ▸ Live Query Statistics) and over a separate connection, shows the state, elapsed time, waits and blocking PIDs of the running query, and the progress reported by `pg_stat_progress_*` for CREATE INDEX, VACUUM, ANALYZE, CLUSTER and COPY. PostgreSQL has no per-operator counters while a query runs, so there is no live plan.

## Object Explorer additions

**View ▸ Object Explorer Details** (`F7`) lists the contents of the selected node (name, type, schema, owner) with a search box; double-click or `Enter` opens an item and `Backspace` goes up. Keys, constraints and triggers have **Modify** (the Table Designer, or a DROP and CREATE script for a trigger), **Rename** (`F2`) and **Delete** with the exact command, never CASCADE; the folders have **New Foreign Key…**, **New Constraint…** and **New Trigger…**, and triggers **Enable** and **Disable**. **New Function…** and **New Stored Procedure…** open templates in a connected query. Each database has an **Extensions** folder with **New Extension…** (schema, version, CASCADE; OK or Script), **Update Extension…** and **Delete**. Tables, materialized views and databases have **Maintenance ▸ Vacuum…**, **Analyze…** and **Refresh Materialized View…**, which open the command in a query tab instead of running it. **Composite Types**, **Foreign Servers** and **Replication** (local publications and subscriptions) are read only; option values and `subconninfo` are not shown. The name and owner filters also have **Does not equal**. **Role Memberships** lists effective memberships, direct and inherited, with the shortest path.

## Schema Compare

**Tools ▸ Schema Compare** compares a source and a target database, chosen in the Connect window, in a read-only transaction. Differences are grouped by type, schema and action (Add, Change, Delete), with the two definitions side by side and the different lines marked. **Generate Script** writes the changes into a query tab connected to the target: `ALTER TYPE … ADD VALUE` first, the rest inside `BEGIN … COMMIT`, tables column by column, and possible data loss marked. PGMS never runs it; review it before executing. There is no Apply, no options page and no `.dacpac` or `.scmp` file.

## When PGMS hits an error

An error that PGMS did not handle is written to a daily log in `%LOCALAPPDATA%\PGMS\logs` (or `logs` under `PGMS_STATE_DIRECTORY`), kept for 30 days. The log has the time, the PGMS, Windows and .NET versions and the exception with its stack; password values written as `key=value` are masked. Nothing is sent over the network. An error in the interface also opens **PGMS - Unexpected Error** with **Copy Details**, **Open Log Folder**, **Report Issue**, **Continue** (the default; your open queries keep their text) and **Close PGMS** (closes normally, still offering to save files). An error in a background thread ends PGMS after logging it. When reporting, read the log first: an error message can quote what the server sent.

## Save and recover

Save SQL files explicitly. Background recovery (every 5 minutes by default; see Tools ▸ Options ▸ Environment ▸ AutoRecover) stores bounded encrypted drafts and may reopen them disconnected after interruption. Review recovered tabs and use **Save As**. This is not a backup system or proof that every latest keystroke was persisted. Conflicting external file changes are refused. Close the app before backing up local state; DPAPI is tied to the Windows user. Builds earlier than M934 cannot read the newer recovery container. See [validation](validation.md) for the exact cross-version recovery tested.
